## 1. Загальна архітектура проєкту

Проєкт являє собою монорепозиторій із повним практичним стендом для навчання, оцінювання та порівняння шести підходів до колоризації зображень. Структура репозиторію поділена на три модулі:

```
ImageColorizationAnsamble/
├── ml/                  ← модуль машинного навчання
│   ├── src/
│   │   ├── models/      ← архітектури моделей
│   │   ├── losses/      ← функції втрат (GAN, перцептуальна, гістограмна)
│   │   ├── algorithms/  ← класичні алгоритми (Welsh, Levin)
│   │   └── utils/       ← dataset, metrics, common
│   ├── scripts/
│   │   ├── trains/      ← 4 окремих скрипти навчання + диспетчер
│   │   └── evaluate.py  ← CLI-пайплайн оцінювання
│   └── tests/           ← pytest
├── api/                 ← Flask REST API
│   ├── routes/          ← training, inference, metrics, models, history
│   └── services/        ← colorizer, classical_colorizer, metrics_service, ...
└── frontend/            ← Vue 3 + Vite SPA (у межах статті не розглядається)
```

Ключовий принцип організації: логіка навчання та оцінювання повністю зосереджена в `ml/`, API є тонким адаптером між клієнтом та тим самим кодом — `api/services/colorizer.py` дзеркально повторює логіку `ml/scripts/evaluate.py`, що гарантує ідентичні результати при запуску через CLI або через HTTP.

## 2. Вибір колірного простору

Усі нейромережеві моделі та пайплайни оцінювання працюють у просторі **CIE L\*a\*b\***. Перехід з RGB до Lab здійснюється функціями `skimage.color`:

| Канал | Діапазон (оригінал) | Нормалізація для мережі |
|---|---|---|
| L (яскравість) | [0, 100] | `/100.0` → [0, 1] |
| a (жовто-синя вісь) | [−128, 127] | `/128.0` → ≈[−1, 1] |
| b (червоно-зелена вісь) | [−128, 127] | `/128.0` → ≈[−1, 1] |

**Мотивація вибору:**
- Канал L фактично є самим чорно-білим зображенням, що виключає потребу мережі вивчати структуру заново.
- Мережа передбачає лише два канали (a, b) замість трьох, що зменшує розмірність виходу та прискорює збіжність.
- Метрична рівномірність простору Lab забезпечує кращу кореляцію L1/L2-функцій втрат із людським сприйняттям, порівняно з RGB.

Нормалізована яскравість й розрахункові ab-канали після інференсу конвертуються назад через `skimage.color.lab2rgb`. Перед конвертацією значення каналів a та b обрізуються до діапазону [−128, 127], щоб запобігти виходу за межі sRGB-гамуту.

## 3. Набір даних та пайплайн підготовки даних

### Набір даних

Для навчання та оцінювання використано **COCO val2017** — публічний набір з понад 5000 реальних кольорових зображень різноманітних сюжетів (люди, транспорт, природа, побут).

- Розташування: `data/coco/val2017/`
- Формати: `.jpg`, `.png`, `.jpeg`
- Підтримка кількісного обмеження: параметр `--num_samples` дозволяє обмежити пул для прискорення ітерацій.

### Клас `ColorizationDataset`

```
ColorizationDataset(
    root_dir,
    mode='train' | 'val' | 'all',
    transform=None,
    val_ratio=0.1,
    seed=42,
    num_samples=None
)
```

Ключові особливості реалізації:
- **Детерміністичне розбиття train/val**: тасування індексів через `np.random.RandomState(seed=42)`, без перетину між вибірками.
- **Відсоток валідації**: за замовчуванням 10% від загального пулу.
- **Перетворення до Lab**: PIL → numpy → `skimage.color.rgb2lab` → нормалізація → PyTorch тензор.
- **Формат виходу**: `{'L': (1, H, W), 'ab': (2, H, W)}`.

### Аугментація

| Вибірка | Трансформації |
|---|---|
| Тренувальна | `Resize(256, 256)` + `RandomHorizontalFlip()` |
| Валідаційна | `Resize(256, 256)` |

## 4. Класичні методи (базові алгоритми)

Обидва методи реалізовані як повністю автоматизовані: кольорові підказки або референс-зображення генеруються програмно, без ручного втручання.

### 4.1 Welsh 2002 — статистичне перенесення кольору

**Реалізація:** `ml/src/algorithms/welsh.py`

**Принцип:** Для кожного пікселя цільового зображення метод знаходить найбільш подібний піксель у кольоровому референсі, порівнюючи два ознаки:
1. значення яскравості L;
2. стандартне відхилення яскравості в локальному вікні 5×5 (грубий дескриптор текстури).

Після знаходження найближчого сусіда (KDTree, складність O(N log N)) значення каналів a та b копіюються з референсу до цільового пікселя.

**Обмеження:** Метод «семантично сліпий» — він легко плутає об'єкти з однаковою яскравістю, але різним кольором (наприклад, блакитне небо та зелена трава).

### 4.2 Levin 2004 — оптимізаційне поширення кольору

**Реалізація:** `ml/src/algorithms/levin.py`

**Принцип:** Мінімізується квадратична функція вартості:

$$J(U) = \sum_{r} \left( U(r) - \sum_{s \in N(r)} w_{rs}\, U(s) \right)^2$$

де ваги $w_{rs} \propto \exp\!\left(-\frac{(L_r - L_s)^2}{2\sigma_r^2}\right)$ забезпечують умову: «сусідні пікселі з близькою яскравістю повинні мати близькі кольори». Мінімізація зводиться до розв'язку розрідженої системи рівнянь Ax = b розміром N×N (де N = H×W), яка розв'язується методом спряжених градієнтів (`scipy.sparse.linalg.cg`).

**Автоматизація:** Кольорові підказки генеруються автоматично шляхом випадкового вибірки пікселів з референсного зображення та їх проєкції на ті самі просторові позиції цільового.

**Обмеження:** Обчислювально дорогий для великих зображень; не розуміє семантику.

## 5. Нейромережеві моделі

Усі чотири моделі утворюють послідовні **стадії**: кожна наступна базується на попередній або використовує її ваги для ініціалізації.

### 5.1 Baseline CNN (Стадія 1)

**Реалізація:** `ml/src/models/baseline_cnn.py`

Проста архітектура encoder-decoder із трьома рівнями кодувальника та трьома відповідними рівнями декодувальника, з'єднаними skip connections (конкатенація по каналах).

```
Encoder:
  enc1: Conv2d(1→64,  stride=2) + BN + ReLU   → (B, 64,  H/2, W/2)
  enc2: Conv2d(64→128, stride=2) + BN + ReLU  → (B, 128, H/4, W/4)
  enc3: Conv2d(128→256, stride=2) + BN + ReLU → (B, 256, H/8, W/8)

Decoder (з skip connections):
  dec1: ConvTranspose2d(256→128) + cat(enc2) → (B, 256, H/4, W/4)
  dec2: ConvTranspose2d(256→64)  + cat(enc1) → (B, 128, H/2, W/2)
  dec3: ConvTranspose2d(128→2)   + Tanh      → (B, 2, H, W)
```

**Функція втрат:** L1Loss  
**Характеристика результату:** Стабільний результат, але схильний до ненасичених «безпечних» кольорів через усереднення при pixel-wise регресії.

---

### 5.2 U-Net (Стадія 2)

**Реалізація:** `ml/src/models/u_net.py`

Повноцінна 8-рівнева U-Net з глибіною повністю до bottleneck 1×1, симетричними skip connections та dropout у глибших блоках.

```
Encoder: down1…down8  (1→64→128→256→512→512→512→512→512)
         Bottleneck: 512 @ 1×1
Decoder: up1…up7      з конкатенацією skip-з'єднань від відповідних down-блоків
Вихід:   Conv2d(128→2) + Tanh → (B, 2, H, W)
```

Кожен `UNetDown` блок: `Conv2d(stride=2) + BatchNorm + LeakyReLU(0.2)` + optional Dropout  
Кожен `UNetUp` блок: `ConvTranspose2d(stride=2) + BatchNorm + ReLU` + optional Dropout + конкатенація skip

**Функція втрат:** L1Loss  
**Характеристика результату:** Суттєво покращена чіткість меж і локальних структур порівняно з Baseline CNN завдяки skip connections, що зберігають деталі яскравості.

---

### 5.3 Pix2Pix GAN (Стадія 3)

**Реалізація:** `ml/scripts/trains/train_gan.py`, генератор = U-Net (Stage 2), дискримінатор = PatchDiscriminator

**Генератор:** архітектура U-Net з 5.2  
**Дискримінатор:** PatchGAN — класифікує перекривні патчі зображення як реальні/фейкові, що змушує генератор дотримуватись локальних реалістичних текстур.

```
PatchDiscriminator:
  initial:      Conv(3→64, stride=2) + LeakyReLU
  intermediate: 64→128→256→512 з Block(stride=2) + stride-1 refinement
  final:        Conv(512→1)   ← patch score map
Вхід: cat[L (1ch), ab (2ch)] = 3 канали
```

**Функція втрат генератора:**
$$\mathcal{L}_G = \mathcal{L}_{GAN} + \lambda_{L1} \cdot \mathcal{L}_{L1} + \lambda_{perc} \cdot \mathcal{L}_{perc}$$
з $\lambda_{L1} = 100$, $\lambda_{perc} = 10$

**Характеристика результату:** Насичені реалістичні кольори. Змагальне навчання долає ефект «сепії», властивий чистій L1-регресії.

---

### 5.4 Fusion GAN (Стадія 4)

**Реалізація:** `ml/src/models/unet_fusion.py`, `ml/src/models/global_hints.py`, `ml/scripts/trains/train_fusion.py`

Ключове нововведення: до bottleneck U-Net вбудовано глобальний семантичний вектор від **GlobalHintNet** — модифікованої ResNet-18.

#### GlobalHintNet

```
Вхід: L-канал (B, 1, H, W) → репліковано до (B, 3, H, W)
Backbone: ResNet-18 (pretrained ImageNet, перший шар адаптований для 1-канального входу)
          Вага першого Conv2d: усереднення RGB-фільтрів по каналам
Вихід:    (B, 512) — вектор глобальних семантичних ознак
Режими:   freeze=True (заморожені ваги, legacy) або freeze=False (спільне навчання з генератором)
```

#### Fusion layer у UNetFusion

```python
# Bottleneck U-Net: d8 → (B, 512, 1, 1)
d8_flat  = d8.view(B, 512)
combined = torch.cat([d8_flat, global_hint], dim=1)  # (B, 1024)
fused    = Linear(1024→512) + ReLU                  # (B, 512)
fused    = fused.view(B, 512, 1, 1)                 # повернення просторових розмірів
```

Після злиття декодер продовжує роботу так само, як у U-Net, використовуючи збагачений контекстом bottleneck.

**Функція втрат генератора:**
$$\mathcal{L}_G = \mathcal{L}_{GAN} + \lambda_{L1} \cdot \mathcal{L}_{L1} + \lambda_{perc} \cdot \mathcal{L}_{perc} + \lambda_{hist} \cdot \mathcal{L}_{hist}$$
з $\lambda_{L1} = 75$, $\lambda_{perc} = 20$, $\lambda_{hist} = 5$

**Характеристика результату:** Найбільша семантична узгодженість серед усіх реалізованих підходів завдяки глобальному контексту сцени та контролю розподілу кольорів.

## 6. Функції втрат

Усі функції втрат розміщені в `ml/src/losses/__init__.py`.

### GANLoss

Реалізована через `BCEWithLogitsLoss`. Підтримує **label smoothing**: реальні мітки дорівнюють `1 − label_smoothing` (за замовчуванням 0.9 замість 1.0), що запобігає перевпевненості дискримінатора та стабілізує навчання.

### PerceptualLoss (VGG-16)

Порівнює активації на шарах `{3, 8, 15, 22}` заморожено VGG-16 між передбаченим та еталонним зображеннями. Оскільки моделі виводять 2-канальний ab, перед подачею до VGG виконується конвертація в pseudo-RGB:

```python
ab_scaled = (ab + 1.0) / 2.0  # [-1,1] → [0,1]
pseudo_rgb = cat([L, ab_scaled], dim=1)  # (B, 3, H, W)
```

VGG-ваги заморожені (`requires_grad=False`), тому функція не вносить у граф додаткових навчальних параметрів.

### HistogramLoss (лише Fusion GAN)

Диференційна функція втрат, яка штрафує за розходження глобальних гістограм каналів a та b між передбаченням та еталоном. Гістограми будуються через «м'який» Gaussian-kernel приближення з 32 бінами у діапазоні [−1, 1]. Це примушує модель узгоджувати загальний розподіл кольорів навіть у пікселях, де попіксельне призначення є неоднозначним.

## 7. Протокол навчання

### Спільні параметри

| Параметр | Baseline CNN | U-Net | GAN | Fusion GAN |
|---|---|---|---|---|
| Оптимізатор | Adam | Adam | Adam (G + D) | Adam (G + D + hint) |
| β₁, β₂ | 0.9, 0.999 | 0.5, 0.999 | 0.5, 0.999 | 0.5, 0.999 |
| Scheduler | StepLR (÷2 кожні epochs/3) | StepLR | LambdaLR (linear decay 2nd half) | LambdaLR |
| Val ratio | 0.1 | 0.1 | 0.1 | 0.1 |
| Аугментація | RandomHFlip | RandomHFlip | RandomHFlip | RandomHFlip |
| Кращий ckpt | за мін. train loss | за мін. train loss | за макс. val PSNR | за макс. val PSNR |

### Покращення GAN-тренування (v2)

Порівняно з наївним тренуванням, у другій версії реалізовано:

1. **VGG perceptual loss** — запобігає ненасиченості кольорів при чистій L1-регресії.
2. **Label smoothing 0.1** — запобігає перевпевненості дискримінатора.
3. **Gradient clipping** (`max_norm=1.0` для генератора) — запобігає вибуху градієнтів.
4. **Warm-start генератора** — ваги GAN-генератора ініціалізуються з навченої U-Net (`--warmstart_g unet_best.pth`), що скорочує час досягнення якісних результатів.
5. **Валідація за PSNR** — найкращий чекпойнт генератора зберігається за максимальним значенням PSNR на валідаційній вибірці, а не за мінімальним значенням функції втрат.

### Рекомендований порядок навчання

```
Stage 1: Baseline CNN   (~16 хв,   epochs=20, batch=16, lr=5e-4)
Stage 2: U-Net          (~90 хв,   epochs=30, batch=8,  lr=1e-4)
Stage 3: Pix2Pix GAN    (~4-6 год, epochs=50, batch=4,  lr=2e-4, warmstart від U-Net)
Stage 4: Fusion GAN     (~5-7 год, epochs=50, batch=4,  lr=2e-4, warmstart від U-Net)
```

### TensorBoard

Усі скрипти підтримують логування в `outputs/runs/` через `SummaryWriter`. Протоколюються `Loss/step`, `Loss/epoch`, `LR`, `Val/PSNR`, `Val/SSIM`, `Loss_Perceptual`, `Loss_Histogram`.

## 8. Пайплайн оцінювання та метрики

### Метрики

| Метрика | Що вимірює | Краще |
|---|---|---|
| **PSNR** | Пікове відношення сигнал/шум, дБ | Вище |
| **SSIM** | Структурна схожість [−1, 1] | Вище (max 1.0) |
| **LPIPS** | Перцептуальна відстань (AlexNet) | Нижче (min 0.0) |
| **inference_time_ms** | Час одного прямого проходу, мс | Нижче |

Реалізація: `ml/src/utils/metrics.py`
- `compute_psnr`: `skimage.metrics.peak_signal_noise_ratio`, data_range=1.0
- `compute_ssim`: `skimage.metrics.structural_similarity` з `channel_axis=2`
- `compute_lpips`: `lpips.LPIPS(net='alex')` — завантажується один раз на рівні модуля
- `time_inference`: точний вимір wall-clock часу з GPU/MPS-синхронізацією

**Важлива особливість:** метрики обчислюються лише в режимі `color_photo`, коли є еталонне (ground truth) зображення. У режимі `grayscale` (справжні чорно-білі фото) метрики завжди `null`, що є коректною поведінкою.

### CLI-пайплайн (`ml/scripts/evaluate.py`)

```bash
python ml/scripts/evaluate.py \
    --model fusion | gan | unet | baseline \
    --checkpoint outputs/checkpoints/fusion_generator_best.pth \
    --img_path data/test_samples \
    --save_dir outputs/images
```

Пайплайн:
1. Завантажує модель та контрольну точку.
2. Для кожного зображення: `L-канал → інференс → ab → RGB → обчислення метрик`.
3. Зберігає порівняльні смужки `[Grayscale | Prediction | Ground Truth]` у PNG.
4. Виводить зведену таблицю з PSNR, SSIM, LPIPS, часом і середніми значеннями.

### Бенчмарк-сервіс (`api/services/metrics_service.py`)

Сервіс підтримує три рівні оцінювання:

| Метод | Опис |
|---|---|
| `evaluate_single(image, model, ckpt)` | Одне зображення, повертає всі метрики |
| `evaluate_samples(model, ckpt, dir)` | Повний тестовий набір, усереднені метрики |
| `benchmark(model_configs, dir)` | Всі моделі (включно з класичними) на тестовому наборі |

Для класичних методів: перше зображення з набору використовується як кольоровий референс, решта — як цільові для оцінювання.

## 9. Управління контрольними точками

### Іменування контрольних точок

| Файл | Опис |
|---|---|
| `baseline_cnn_best.pth` | Найкращий Baseline CNN (мін. training loss) |
| `unet_best.pth` | Найкращий U-Net (мін. training loss) |
| `gan_generator_best.pth` | Найкращий генератор GAN (макс. val PSNR) |
| `gan_discriminator_epoch_N.pth` | Дискримінатор на епосі N |
| `fusion_generator_best.pth` | Найкращий gen. Fusion GAN (макс. val PSNR) |
| `*_epoch_N.pth` | Чекпойнти кожні 5 епох |
| `*_final.pth` | Останній стан після завершення навчання |

### Формат збереження

- **CNN і U-Net:** зберігається `model.state_dict()` безпосередньо.
- **Fusion GAN:** зберігається dict `{'model_state_dict': ..., 'hint_net_state_dict': ...}`, щоб можна було відновити обидва компоненти.
- **GAN-генератор:** аналогічно зберігається `model.state_dict()`.

### LRU-кеш у Colorizer

`api/services/colorizer.py` підтримує LRU-кеш на 4 моделі одночасно, що дозволяє обробляти запити до різних моделей без повторного завантаження ~100 МБ ваг на кожен HTTP-запит.

## 11. Підтримка обладнання

Система автоматично обирає найкращий доступний прискорювач:

```
Пріоритет: Apple Silicon MPS → NVIDIA CUDA → CPU
```

Реалізація в `ml/src/utils/common.py → get_device()`. Усі тензори та моделі явно переносяться на обраний пристрій. Для MPS встановлюються два оточувальних параметри:

```bash
PYTORCH_ENABLE_MPS_FALLBACK=1     # операції без MPS-підтримки → CPU
PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.0  # знімає 60%-обмеження unified memory
```

Для вимірювання часу інференсу `time_inference()` виконує синхронізацію пристрою (`torch.cuda.synchronize()` / `torch.mps.synchronize()`) до та після прямого проходу, що дає точну wall-clock затримку без впливу асинхронного виконання ядер.

| Обладнання | Рекомендований batch_size |
|---|---|
| Apple M-series (MPS) | 4–8 |
| NVIDIA GPU (≥8 GB VRAM) | 8–16 |
| CPU | 2–4 |
